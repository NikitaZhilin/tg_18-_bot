# Эксплуатация

## Сервер

- Код: `/opt/tg_18_bot` (git checkout), окружение `.venv`, настройки `/opt/tg_18_bot/.env`.
- Сервис systemd: `tg-18-bot` (`systemctl status tg-18-bot`, `journalctl -u tg-18-bot`).
- База SQLite: путь из `DATABASE_PATH`.
- Бэкапы: `/var/backups/tg-18-bot`.

## Деплой

`.github/workflows/ci-deploy.yml`, push в `main`:

1. **CI:** аудит карточек (`scripts/audit_card_content.py`), dry-run импорта обоих CSV, smoke-test,
   весь pytest. Итог pytest видно в аннотациях запуска.
2. **Deploy** (только `main`): по SSH (секреты `DEPLOY_HOST`, `DEPLOY_PORT`, `DEPLOY_USER`,
   `DEPLOY_PASSWORD`) запускается `scripts/deploy_server.sh`:
   - проверки повторяются в отдельном worktree;
   - бэкап базы;
   - перезапуск сервиса и проверка свежего heartbeat (`scripts/health_check.py`);
   - при неудаче — откат на прежний commit и прежнюю базу;
   - установка и обновление таймеров бэкапа.
3. **После деплоя** — проверка сервера (ниже).

На pull request выполняется только CI. Миграции применяются при старте бота, каждая — в одной
транзакции вместе с записью в `schema_migrations`.

## Бэкапы

| Что | Когда | Где |
|---|---|---|
| Перед каждым деплоем | при деплое | `/var/backups/tg-18-bot` |
| `tg-18-bot-backup.timer` | ежедневно 03:30 (время сервера), хранится 14 дней | `/var/backups/tg-18-bot` |
| `tg-18-bot-offsite.timer` | воскресенье 12:00 МСК | gzip-копия в Telegram владельцам из `ADMIN_TELEGRAM_USER_IDS` (не больше трёх получателей) |

Восстановление: остановить бота, распаковать `.gz`, выполнить
`scripts/restore_database.py <файл> <путь к базе>`, запустить бота.

## Проверка сервера

`.github/workflows/server-health.yml` запускается ежедневно в 08:15 МСК, после каждого деплоя,
вручную (workflow_dispatch) и при push в ветку `ops/health`. Скрипт `scripts/server_health.sh`
только читает и ничего не меняет. Вывод маскируется: репозиторий публичный, ID и IP заменяются
на `<id>` и `<ip>`.

Что показывает: нагрузку, память и диск; развёрнутый commit; состояние и перезапуски сервиса;
ошибки в журнале за сутки; число бэкапов и возраст последнего; таймеры и последнюю отправку
копии; возраст heartbeat; последнюю миграцию; целостность базы; версию SQLite; таймеры игры;
открытые жалобы на карточки; режим игроков и число разрешённых аккаунтов; разрешено ли боту
вступать в группы; число личных и групповых чатов; задан ли пароль для групп, сколько групп
открыто; включена ли игра на троих. Проблемы выводятся строками `WARN:` и становятся
предупреждениями в GitHub.

## Ошибки

Непредвиденная ошибка в обработчике: игрок видит короткое сообщение, владельцам приходит отчёт
(одинаковые — не чаще раза в 10 минут, `app/services/error_report.py`). Нажатие на кнопку из
старого сообщения отвечает «кнопка устарела» (`app/handlers/fallback.py`). Незаконченные диалоги
админки сбрасываются через 2 часа.

## Безопасность

- Репозиторий публичный: токены, пароли и Telegram ID — только в `.env` на сервере и в секретах
  GitHub.
- Пароль для групп задаётся в админке и хранится как PBKDF2-SHA256 (300 000 итераций, соль);
  сообщение с паролем бот удаляет.
- Доступ в личке — по `ALLOWED_TELEGRAM_USER_IDS`; в группе — только участники, нажавшие
  «🙋 Я играю» в открытой паролем группе; если в группе больше людей, чем игроков, карточки
  не показываются.
- Деплой по паролю SSH — сознательное решение владельца; SSH-ключ и отдельный пользователь
  остаются в списке улучшений.
