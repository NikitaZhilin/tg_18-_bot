## Важная граница

Я не буду готовить графические сексуальные инструкции или опасные БДСМ-практики. Даже если бот приватный, в ТЗ и контент-модели нужно исключить сценарии с реальным риском травм, дыхательным контролем, отсутствием быстрого освобождения, принуждением без отдельного согласия, опьянением как условием сцены и медицинскими рисками.

Можно сделать контент значительно более взрослым и интенсивным за счет:

- власти и правил;
- контроля темпа;
- ограничения выбора;
- сенсорного контраста;
- ритуалов;
- психологического напряжения;
- ожидания;
- запретов;
- строгих ролей;
- aftercare.

`hard` в этом проекте должен означать "сильно по эмоциям и роли", а не "опасно для тела".

## Правила интенсивности

### Уровень 1

Фокус:

- романтика;
- доверие;
- внимание;
- прикосновения без давления;
- расслабление.

Интенсивность не дробим. Все карточки считаются `light`.

### Уровень 2

Фокус:

- соблазнение;
- прелюдия;
- игра с ожиданием;
- легкие ограничения;
- массаж;
- сенсорные элементы.

Интенсивность не дробим в интерфейсе, но технически можно ставить `light` или `medium`.

### Уровень 3

`light`:

- мягкая смена темпа;
- романтическая близость;
- простые позы;
- фокус на контакте, ритме и паузах без риска.

`medium`:

- более выраженный контроль темпа;
- ограничения движений без связывания;
- команды внутри сцены;
- смена локации в пределах безопасного пространства;
- таймеры.

`hard`:

- строгий сценарий роли;
- контроль правил;
- запреты;
- испытание выдержки;
- более интенсивная психологическая игра;
- ясное завершение и, при необходимости, aftercare.

### Уровень 4

`light`:

- символическое доминирование;
- протоколы;
- простое подчинение;
- сенсорные ограничения;
- безопасная фиксация с быстрым освобождением.

`medium`:

- более строгие правила;
- ритуалы разрешения;
- контролируемые запреты;
- сценарии служения;
- короткие сцены с явным окончанием.

`hard`:

- высокий психологический контроль;
- строгая сцена с заранее выбранными границами;
- обязательное стоп-слово;
- обязательная проверка состояния до и после;
- обязательный aftercare.

## Что нельзя добавлять в бота

| Категория | Решение | Причина |
|---|---|---|
| Несовершеннолетние или неясный возраст | Запрещено | Нельзя допускать даже намека на возрастную неопределенность |
| Несогласие, принуждение, шантаж | Запрещено | Игра должна строиться только на явном согласии |
| Недееспособность, сон, сильное опьянение | Запрещено | Нет валидного согласия |
| Контроль дыхания, удушение, перекрытие воздуха | Запрещено | Высокий физический риск |
| Травмы, кровь, порезы, иглы, оружие | Запрещено | Риск вреда здоровью |
| Фиксация без быстрого освобождения | Запрещено | Риск паники, травмы, нарушения кровообращения |
| Фиксация шеи или риск кровообращения | Запрещено | Повышенная опасность |
| Огонь, небезопасный воск, электричество | Запрещено для MVP | Риск ожога/травмы |
| Публичные сценарии с посторонними | Запрещено | Нет согласия третьих лиц |
| Фото/видео без согласия, отправка приватных материалов | Запрещено | Приватность и юридический риск |
| Сцены с не-человеческими участниками | Запрещено | Недопустимый контент |
| Самоповреждение | Запрещено | Риск вреда |
| Неограниченное унижение | Запрещено | Нужны заранее заданные границы |
| Необратимые следы и повреждения | Запрещено | Риск долгосрочного вреда |

## Что отправлять на ручную проверку

Новые или спорные темы импортируются как `needs_review` и не включаются в игру до решения
администратора:

- унижение в мягкой форме;
- pain play без травм;
- wax play только со специальной низкотемпературной свечой;
- сенсорная депривация;
- связывание с быстрым освобождением;
- strict roleplay;
- denial-сценарии;
- еда/напитки;
- игрушки.

Для таких карточек нужны понятные `risk_tags`, `aftercare_required = 1` там, где после сцены
нужно отдельное завершение, и `review_status = needs_review` до ручного одобрения.
Согласие обоих игроков подтверждается один раз в сутки перед началом игры, а границы
текущей сессии исключают несовместимые карточки.

## Что сделать с текущими заданиями BDSM

Нужна ручная ревизия.

Предварительная оценка:

- карточки с сенсорными ограничениями можно оставить после добавления стоп-слова и таймера;
- карточки с воском - только при явной пометке `needs_review`, специальном реквизите и safety-тексте;
- карточку с контролем дыхания нужно отключить;
- карточки с унижением нужно оставлять только с отдельным тегом границ;
- карточки со связыванием должны требовать быстрый способ освобождения.

`Экстрим` не является дублем BDSM или жесткой интенсивности. Это отдельная коллекция
`restricted_content`, которая скрыта до включения администратором для текущей сессии.

## Пример безопасного формата карточек

Формат текста должен быть взрослым, но не графическим:

```text
Сцена контроля темпа: один партнер задает правила движения и пауз на 3 минуты. Второй партнер может в любой момент сказать стоп-слово. После таймера оба коротко говорят, что было хорошо и что стоит изменить. [Таймер: 3 минуты]
```

```text
Ритуал разрешения: перед продолжением партнер должен попросить разрешение на следующий шаг. Доминант может разрешить, отложить или дать короткую паузу. Стоп-слово активно в любой момент. [Таймер: 5 минут]
```

```text
Сенсорная сцена: используйте повязку и заранее выбранные безопасные прикосновения. В начале подтвердите границы, в конце снимите повязку и сделайте aftercare. [Реквизит: Повязка, Таймер: 5 минут]
```

## Улучшения для бота

### 1. Выбор интенсивности

После выбора уровня 3 или 4 бот спрашивает:

```text
Выбери интенсивность:
```

Кнопки:

- `[Легкие]`;
- `[Средние]`;
- `[Жесткие]`.

Отдельного переключателя жесткого режима нет: интенсивность является обычным фильтром
выборки. Закрытая коллекция `Экстрим` включается только из админки.

### 2. Настройки границ

Перед уровнем 4 добавить настройку "что сегодня точно нельзя".

Пример тегов:

- без фиксации;
- без унижения;
- без боли;
- без сенсорной депривации;
- без еды/напитков;
- без воска;
- без игрушек.

Эти теги должны исключать карточки из выборки.

### 3. Aftercare

Для карточек с `aftercare_required = 1` после завершения показывать:

```text
Сцена завершена. Сделайте aftercare: вода, тепло, спокойный контакт, короткое обсуждение.
```

Кнопки:

- `[Все хорошо]`;
- `[Пауза]`;
- `[Завершить игру]`.

### 4. Ручная модерация

Новые карточки должны иметь `review_status = draft`.

В игру попадают только:

```text
is_enabled = 1
review_status = approved
```

Практический интерфейс для этого - Telegram-админка `/admin`: черновик, preview, отправка на проверку, одобрение, отключение, история версий и экспорт базы.

## Позы в стиле камасутры

Позы лучше хранить отдельно от `task`-заданий как `category = pose` и коллекцию `kamasutra_inspired_poses`.

Стартовый неграфичный набор лежит в `docs/kamasutra-pose-pack.md`. Его нужно импортировать по тем же правилам модерации:

- сначала `review_status = needs_review`;
- сначала `is_enabled = 0`;
- для карточек, требующих отдельного завершения, ставить `aftercare_required = 1`;
- не использовать карточки с дыхательным контролем, травмами, небезопасной фиксацией и публичными сценариями.

## Рекомендуемый следующий шаг

1. Сделать `content/cards.csv`.
2. Импортировать текущие `13-24`.
3. Автоматически пометить рискованные карточки.
4. Восстановить `1-12` для уровней 1-2.
5. Подготовить безопасные non-graphic карточки для уровней 3-4 по матрице `16/16/16`.
6. Импортировать стартовый пакет поз `kamasutra_inspired_poses`.
7. Провести ручной review через `/admin`.
8. Только после этого грузить карточки в рабочую БД.
