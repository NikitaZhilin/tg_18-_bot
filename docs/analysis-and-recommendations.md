# Итоговый анализ реализации

Дата: 2026-07-28.

## Вывод

Проект вышел из состояния набора Telegram callback-обработчиков. Игровое состояние,
административные сценарии, таймеры и пользовательские настройки теперь восстанавливаются из
SQLite. Основные риски потери данных и расхождения интерфейса с ТЗ закрыты.

## Что улучшено

- Удалены дубли `Уровень 4` и `Жесткий режим`.
- BDSM оставлен обычным разделом, а `Экстрим` оформлен отдельной закрытой коллекцией.
- Согласие учитывает обоих виртуальных игроков даже при одном Telegram-аккаунте и хранится
  отдельно по слотам один календарный день.
- `Заменить карточку` не теряет текущую карточку, если замены нет.
- Реквизит, границы и FSM админки больше не зависят от памяти процесса.
- Желания получили виртуального владельца, список и действие использования.
- Seed-обновления больше не пропускают локальные изменения молча.
- Историю карточки можно просматривать и восстанавливать.
- Таймер имеет claim, backoff и предел попыток.
- Добавлена очередь непонятных карточек.
- Удален скрипт, способный перезаписать актуальный набор контента.
- Добавлен CI/CD с тестами, SQLite backup, heartbeat и rollback.

## Архитектурный итог

Крупные области разделены:

- основной игровой поток и настройки сессии имеют разные routers;
- мастер карточки и операции импорта/экспорта имеют разные routers;
- игровые настройки вынесены из `GameService` в отдельный mixin;
- чтение файлов вынесено из `ContentImporter`;
- желания и обратная связь имеют собственные services и handlers.

Это уменьшает риск, что изменение импорта затронет игровой ход или что настройка реквизита
сломает основную навигацию.

## Остаточные риски

1. Telegram API не поддерживает idempotency key для `sendMessage`. Claim таймера сильно
   сокращает повторы и ограничивает retry, но аварийное завершение процесса между успешной
   отправкой и записью `completed` теоретически может дать один повтор после истечения lease.
2. Деплой по паролю сохранен по решению владельца. Это слабее SSH-ключа и отдельного
   системного пользователя.
3. Telegram-интерфейс ограничивает сложные массовые правки. Для сотен карточек XLSX остается
   основным редактором.
4. Старые исторические миграции содержат поля, которые удаляются последующими миграциями.
   Это нормально: источником итоговой схемы является вся последовательность миграций.

## Следующие улучшения

- Добавить периодическую проверку восстановления последнего backup на отдельной копии.
- Вывести счетчики новых feedback и seed-конфликтов прямо в название кнопок админки.
- Добавить интеграционный тест aiogram Dispatcher с синтетическими callback updates.
- Добавить структурированную метрику длительности deploy и количества rollback.
- После отдельного решения владельца перейти на SSH-ключ и непривилегированного пользователя.
