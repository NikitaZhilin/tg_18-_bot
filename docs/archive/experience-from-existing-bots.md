## Переносимые решения

### 1. Приватность

Использовать env-whitelist:

```text
ALLOWED_TELEGRAM_USER_IDS=...
ALLOW_UNLISTED_USERS=false
```

Неавторизованные пользователи не должны создавать записи в игровых таблицах.

### 2. Разделение контекста

Из старого Telegram-бота полезен `chat_key`:

```text
chat_id:thread_id
```

Для текущего бота это важно, если позже игра будет идти не только в личке, но и в общем чате или topic.

### 3. Бизнес-логика вне Telegram handlers

Из `tg_bot_inkubator` нужно перенести структуру:

```text
handlers -> services -> repositories -> SQLite
```

Так можно тестировать игру без реального Telegram update.

### 4. Кнопочные сценарии в MVP

Инкубатор показал, что сложные сценарии лучше делать через кнопки и FSM, а не через свободный текст.

Для текущего бота:

- выбор реквизита;
- выбор уровня;
- выбор категории;
- включение уровня 4;
- пропуск;
- стоп-слово;
- таймер

должны быть кнопочными и предсказуемыми.

### 5. Специальные режимы отдельной веткой

В инкубаторе был реальный UX-баг: сценарий "уже скормленный замес" оказался спрятан внутри обычного чек-листа.

Для текущего бота это правило переносится так:

- безопасный пропуск не должен запускать штраф;
- stopword не должен вести через обычный reset;
- уровень 4 не должен быть обычной кнопкой без отдельного согласия;
- рулетка должна проходить через те же фильтры безопасности.

### 6. Runtime-устойчивость

Практические проблемы из инкубатора:

- бот может умереть без автоподъема;
- pid может быть stale;
- Telegram может быть недоступен по сети;
- нужна поддержка proxy;
- на Windows может не быть `tzdata`;
- `.venv` может не использоваться скриптами.

Для нового бота сразу закладываются:

- `scripts/start-bot.ps1`;
- `scripts/stop-bot.ps1`;
- `scripts/status-bot.ps1`;
- `scripts/smoke_start.py`;
- retry polling;
- `TELEGRAM_PROXY_URL`;
- `app_heartbeats`.

### 7. Контент вне кода

В инкубаторе база знаний была отделена от кода. Для текущего бота карточки тоже должны жить отдельно:

```text
content/cards.csv
```

Импорт должен быть проверяемым и воспроизводимым.

### 8. Проверки

Минимальный контроль качества:

- SQL-схема валидируется в SQLite `:memory:`;
- content CSV проходит `--check`;
- services покрыты unit-тестами;
- callback/FSM сценарии покрыты регрессиями;
- smoke-запуск проверяет конфиг и инициализацию.

## Что не переносить

- Свободный AI-чат из старого Telegram-бота не нужен в MVP.
- Voice-сообщения не нужны в MVP.
- Напоминания дневника не нужны как постоянный шум, но подход с runner-ом полезен для таймеров.
- Web-интерфейс инкубатора не нужен на старте.

## Итог

Лучший путь для текущего бота: сначала сделать надежное детерминированное ядро игры, затем Telegram UI, и только после стабилизации думать об AI, админке или расширенных режимах.
