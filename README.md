# tg_18_bot

Приватный Telegram-бот для пошаговой игры двух взрослых партнеров.

## Быстрый старт

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
python scripts\smoke_start.py
python scripts\import_cards.py --check content\cards.csv
python -m pytest -q
```

Для реального запуска заполнить `.env`:

```text
BOT_TOKEN=
ALLOWED_TELEGRAM_USER_IDS=
ADMIN_TELEGRAM_USER_IDS=
PLAYER_1_NAME=
PLAYER_2_NAME=
SINGLE_ACCOUNT_TWO_PLAYERS=false
ADMIN_CONTENT_PASSWORD_SHA256=
DATABASE_PATH=./data/bot.sqlite3
```

Токены, пароли и приватные ID не коммитятся.

Если два человека играют с одного Telegram-аккаунта, укажите один `ALLOWED_TELEGRAM_USER_IDS`
и включите:

```text
SINGLE_ACCOUNT_TWO_PLAYERS=true
```

Перед первой игрой за календарный день бот последовательно запрашивает подтверждение
`Игрока 1` и `Игрока 2`. В режиме одного аккаунта это два отдельных нажатия с одного
Telegram User ID. После кнопки `Завершить игру` подтверждение в тот же день не повторяется.

Раздел `Экстрим` не показывается в игре по умолчанию. Для доступа админ открывает
`Админка -> Экстрим: доступ закрыт`, вводит пароль, и текущая сессия получает доступ к карточкам
из коллекции `restricted_content`. Обычные переключатели уровня 4 и жесткой интенсивности для
этого раздела не требуются. В `.env` хранится только SHA-256 пароля:

```powershell
python -c "import hashlib, getpass; print(hashlib.sha256(getpass.getpass().encode()).hexdigest())"
```

Настройки реквизита действуют в пределах текущей сессии. Для каждого предмета выбирается
частота `выключен / редко / иногда / часто`; бот добавляет только предметы, совместимые с
уровнем и типом выпавшей карточки.

Кнопка `В меню` не завершает активную карточку. Прогресс хранится в SQLite, а вернуться к
карточке можно кнопкой `Продолжить текущую карточку`.

Кнопка `Заменить карточку` закрывает текущую карточку и сразу выдает другую с теми же
настройками тому же игроку. Если подходящей замены нет, активная карточка не меняется.
В настройках уровней можно исключить уже пройденные разделы из общей рулетки.

В режиме одного аккаунта желания закрепляются за виртуальным игроком. Сохраненные купоны
доступны из главного меню, где их можно открыть и использовать в ход владельца.

Админка содержит каталоги карточек и реквизита. Экспорт создает русскую XLSX-книгу с отдельными
листами уровней, листом `Экстрим`, справочниками и раскрывающимися списками. Этот же файл можно
загрузить обратно через `Импорт XLSX`. Админка также позволяет восстановить версию карточки,
разрешить конфликт встроенного обновления и обработать жалобу на непонятный текст.

## Проверка и развёртывание

Workflow `.github/workflows/ci-deploy.yml` при push в `main`:

1. запускает аудит карточек, dry-run импорта, smoke-test и весь pytest;
2. передает проверенный commit на сервер;
3. сервер повторяет проверки в отдельном worktree;
4. создает резервную копию SQLite;
5. перезапускает systemd-сервис и проверяет свежий heartbeat;
6. автоматически возвращает прежний commit и базу при неуспешном health-check.

GitHub Actions использует secrets `DEPLOY_HOST`, `DEPLOY_PORT`, `DEPLOY_USER` и
`DEPLOY_PASSWORD`. Серверный запуск выполняется скриптом `scripts/deploy_server.sh`.

## Команды

- `/start` - старт и игровое меню;
- `/help` - справка;
- `/status` - технический статус для владельцев;
- `/admin` - Telegram-админка контента;
- `/reset` - завершить сессию после подтверждения;
- `/stopword` - мгновенно остановить сессию.
